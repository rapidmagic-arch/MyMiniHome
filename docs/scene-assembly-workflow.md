## 1. 원인과 첫 템플릿의 선택
기존 배경은 원근이 있는 **평면 원경**이었지만, 개별 오두막·나무·연못·폭포는 서로 다른 **아이소메트릭/투영 및 크기**를 지님. 지면 픽셀 접점(foot anchor), 지형 레벨, 조명과 가림 순서가 미확정이라 독립 이미지를 화면 좌표에 붙이기만 해서는 떠 보임.

**현 단계 우회/검증 방법(임시):** 배경·건물·연못·다리·폭포가 이미 조화롭게 배치된 **마스터 장면을 한 장으로 고정**하여 재배치하지 않고, 독립 캐릭터만 실제 발 위치 기준으로 배치함. 구조물은 이미지와 분리된 투명 클릭 히트박스로 선택 가능하게 둠. 단, 이 방법은 건축물·물의 독립 애니메이션/재배치를 제공하지 않으며 최종 분리 자산 제작의 대체물이 아님.

## 2. 첫 템플릿 설계 기준
- 한 가지 정규 좌표계: **1774×887 원본 픽셀**. 화면 크기에 따라 비율 유지하여 동일한 전체 장면을 스케일한다.
- 캐릭터는 `(x, y)`를 화면 내 **발/접지점 좌표**로 정의한다. 각 스프라이트의 투명 패딩을 고려한 `footFraction`을 적용하며 현재 값은 **시범 수치**, 개별 이미지 QA로 확정 필요.
- 고정 장면의 오브젝트는 **원본 이미지 내 위치를 다시 이동하지 않음**. 클릭 위치만 별도 핫스팟 좌표로 정의한다.
- z-order: 배경 → 핫스팟(투명) → 캐릭터(시범) → 프로필 팝업. 향후 지형 전경/후경 가림 순서에 맞춰 확대.
- 물/언덕/상단 나뭇가지에 캐릭터를 놓지 않는 배치 구역 검사 필요. 현재는 육안으로 선정한 접지 후보 4곳.
- 네이티브 ChatGPT 대화창을 재구현하지 않고, 연결 대상은 확인된 기존 URL만 바인딩.

## 3. 다음 회차 재개 절차(순서와 완료 기준)
1. **원본·현황 읽기:** 이 문서, `scenes/forest-village-v1/index.html`, `docs/assembly-validation-v0.3.md`, `assets/review/background-isolated-v0.2/QA_REPORT.md` 및 GitHub HEAD 확인. 추가 템플릿 제작 없이 **1종을 수정**.
2. **지면/접지 검증:** 실제 원본 이미지상의 물/길/잔디/절벽에 대한 마스크 또는 수작업 영역을 정함. 모든 독립 오브젝트는 자산의 `anchor`와 지면의 접점이 일치하는지 확인. **완료 기준:** 선정한 자산이 지면에서 떠 보이거나 지면 아래로 잠기지 않음.
3. **스케일·투영 일치:** 캐릭터 발 위치, 인접 오브젝트 비례, 공통 2:1 아이소메트릭 지형 footprint, 조명/그림자 기준 비교. 지형 타일 연결이 필요하면 서로 다른 추출 타일을 먼저 정규화. **완료 기준:** 동일한 타일/오브젝트가 접점에서 눈에 띄게 어긋나지 않음.
4. **필요 자산만 교체:** `background-isolated-v0.2`의 53개 후보에서 실제 장면에 사용할 개별 오브젝트만 선정. 경계 접촉 38개는 **잘림 확정이 아니라 검사 대상**; 눈에 띄는 halo·기계적 경계·이웃 픽셀을 보정한 후 사용. 원본/검토본을 덮어쓰지 않음.
5. **클릭·UI 검증:** 건물/우체통/다리 등 히트박스 위치와 캐릭터 팝업을 화면 크기별로 점검. URL은 확인된 프로젝트/GPT 대상만 입력. 클릭 영역과 가림/포커스 접근성 점검.
6. **독립 모션(후속):** 물줄기·연못 물결·잎·우체통 반응은 정적 베이스와 별도 프레임 및 제어 데이터로 분리. 정적 장면의 자연스러움을 먼저 확인한 후 진행하며 현재 모션 완료로 표시하지 않음.
7. **조립 회귀 검증:** 단일 장면을 다른 화면 너비에서 렌더링하여 비율·접지·가림·UI/클릭 검사. 실패 시 해당 자산/좌표만 수정. 원본 마스터와 화면 구성 비교.
8. **버전·인계 기록:** 장면 파일, 사용하는 자산의 경로/해시, 승인/보류 판정, 시험 화면, 다음 작업 항목을 업데이트. 사용자 채택 여부와 기술 테스트 통과를 구별.

### 첫 템플릿의 실제 검증 수준

## 4. 'Git에는 최종본만' 운영 규칙 제안 — 미확정, 미적용

**핵심 문제:** `main`에는 SVG 프로토타입 9개, 검토 v0.1 15개, 캐릭터 v0.2 76개, 분리 이미지 v0.2 58개 등 검토 자료가 남음. 그러나 지금 생성된 단일 장면은 **두 개의 `assets/review/` 경로를 직접 참조**함. 지금 이들을 삭제하면 템플릿이 깨짐. 또한 '최종본'으로 사용자 채택된 자산은 아직 없음.

**권고 운영안:** 
- `main`에서 **현행 템플릿 1종 + 현재 참조 중인 자산 + 필수 설계/검증 문서**만 개발 대상으로 노출.
- 새 자산이 실제 조립·품질 검증과 사용자 채택을 마친 뒤에만 `assets/runtime/` 등 최종 사용 경로로 **이동/승격**한다.
- 레거시 삭제 전 **Git 커밋/태그/브랜치로 원본 식별 가능하도록 보존**, 코드/문서/매니페스트의 참조를 새 경로로 변경하고 이미지 로드·회귀 테스트 후에만 오래된 `assets/review/*`를 `main`에서 정리한다.
- `git rm`으로 최신 트리에서 제외해도 Git **과거 커밋의 바이너리는 자동 삭제되지 않음**. 진짜 저장소 용량 감소를 원할 때는 별도 후속 정책이 필요하다.
- 레거시 범위(모든 이미지/모든 SVG/참조되지 않는 것만)와 최종 승인 시점을 사용자 확정 전까지 **정리 제안**으로 유지. 현 단계에서 대규모 삭제·Git 히스토리 재작성·브랜치 삭제를 실행하지 않음.

### 전환의 상태 의미
`review_candidate` → `assembled_prototype` → `visual_qa_passed` → `user_approved_final` → `runtime_active` → (대체된 자산의 경우) `archived`

- 기술 QA 통과는 자동 사용자 승인이나 최종 반영 권한을 의미하지 않음.
- 후속 자산 채택은 **사용자 확정과 적용 범위**에 따라 이루어진다.
- 이번 실제 상태: `assembled_prototype`; **최종본 아님**, 자산 삭제 **미수행**.

## 5. 다음 세션 시작점
`scenes/forest-village-v1/index.html`에 있는 `<script id="scene" type="application/json">`이 **단일 템플릿의 좌표 원본**이다. 같은 데이터를 중복 복사해 다른 확정값을 만들지 말 것. URL이 미확정이면 `null` 그대로 유지.

우선 확인할 항목: ① 장면의 캐릭터 접지·크기 ② 작은 패널에서 팝업 가독성 ③ 53개 분리 자산의 실제 재사용 적합성 ④ 기존 아카이브/정리 범위의 사용자 결정. 요구하지 않은 새 템플릿 생성·앱 배포는 포함하지 않음.
