# MyMiniHome 기본 장면 v1 — Chromium 브라우저 검증 (2026-11-23)

## 판정
**시제품 상호작용·반응형 기본 기능 통과 / 자연스러운 보행 연출 미통과 / ChatGPT 호스트 연동 미검증.**

검증 대상: `scenes/forest-village-v1/index.html`, 사용자 확정 Q1~Q6 유지, 단일 장면만 수정.

### 실제 발견·수정
1. **6프레임의 잘못된 용도:** 다람쥐·토끼·여우·늑대 24개 원본 프레임은 걷기 전용이 아니라 표정·제스처·점프가 섞여 있음. 특히 squirrel 04, rabbit 05, fox 05를 보행 루프에 쓰면 캐릭터가 튀어 보임.
   - **수정:** 순찰 중 프레임을 `[1,2,3,6]`로 한정하고 900ms 간격으로 표정/제스처만 전환. 수평 위치는 부드럽게 이동, 최대 ±1.1px 정도의 미세 보브. 실제 보행 모션으로 승인하지 않음.
   - **부수 수정:** 이동 방향 반전 `scaleX(-1)`을 제거해 손에 든 책/지도/화면이 거울처럼 뒤집히지 않도록 함.
2. **움직이는 버튼 클릭 불안정:** 최초 Chromium 테스트에서 캐릭터 버튼 위치가 프레임마다 이동해 실제 클릭 자동화가 `element is not stable`로 실패함.
   - **수정:** 캐릭터 클릭 버튼의 사각형 영역은 정적인 순찰 구간 중심에 고정하고, 버튼 안의 PNG만 움직이는 방식으로 변경. 그림자도 `--sprite-dx`로 해당 위치를 추적.
   - **재검증:** 실제 포인터 클릭으로 캐릭터 프로필 표시, Esc 닫기 성공.
3. **작은 화면 화면 관리:** 최소 장면 배율 0.52배(장면 너비 약 922px). 좁은 화면은 가로 스크롤, 필요 시 전체 보기 버튼으로 축소. 팝업은 장면과 독립된 크기로 유지.

## 테스트 도구와 증거 경계
- Python Playwright + `/usr/bin/chromium` headless에서 실제 브라우저 레이아웃·입력·스크롤·스크린샷 수행.
- Chromium 보안 환경에서 GitHub/raw URL 및 `file://` 네비게이션이 차단되어 **실제 GitHub 페이지를 그대로 로드한 것은 아님**.
- **현행 GitHub의 런타임 JS를 동일하게 복제한 로컬 HTML 시험 하네스**에서 테스트. 페이지의 이미지 URL만 로컬 data URI로 치환했으며, HTML 구조와 CSS는 검증 대상의 핵심 레이아웃을 재현한 로컬 미러임(모든 HTML/CSS 바이트가 동일한 것은 아님).
- **스크립트 일치 확인:** GitHub 런타임 JS에서 프레임 URL 생성식만 로컬 data URI 맵 접근으로 바꾼 내용과 로컬 하네스 JS의 글자 단위 FNV32가 동일(`2ceb9c0f`, 길이 6804자). 이 보조 지문은 암호학적 SHA-256이 아니며 **화면/호스트 동등성 보증은 아님**.
- 배경 1장과 캐릭터 4종의 원본 ZIP 데이터에서 로컬 data URI를 생성하여 브라우저에 사용. 프레임은 미리보기 용도로 240×240으로 리샘플해, **최종 고화질·원본 픽셀 경계 검사와 구별**.

## 남은 품질 위험과 후속
- **핵심 미충족:** 걷기 전용 각 방향 모션과 보행 주기/그림자/발 접촉이 부족. 현재는 표현·제스처 시트만 활용한 짧은 순찰 시안임.
- 현재 `actor` 정적 클릭 영역은 전체 순찰을 덮어 UX 안정성을 높였으나, 실제 가시 캐릭터 실루엣에 정확히 맞는 히트박스는 아님. 불필요한 공백 클릭 여부를 장면에서 추가 점검.
- HTML/CSS와 이미지 원본 품질의 **완전 동일 렌더링**, 실제 모바일 터치 장치, 실제 ChatGPT Conversation Panel 호스트는 아직 검증하지 않았음.
- 8종 중 현재 4종만 표시; owl/bear/frog/hedgehog의 장면 배치/모션은 후속.
- 기존 프로젝트/GPT URL은 `null`이며 ChatGPT 메시지 전송·자동 신규 채팅 생성은 미구현. 우체통 입력은 화면 내 미리보기만 제공.
- 레거시 `assets/review/` 자산 삭제는 수행하지 않음. 사용 중인 참조 경로 정리/최종 채택을 마치기 전의 삭제는 피함.

**다음 작업 순서:** (1) 걷기 전용 모션 생성·발 앵커 정합성 QA → (2) 캐릭터 별 상호작용/접지·동선 확정 → (3) 모바일/ChatGPT 패널 실제 호스트 UX 검증 → (4) 승인된 runtime 자산으로 승격 → (5) 참조 변경 검증 후 레거시 main 정리.
