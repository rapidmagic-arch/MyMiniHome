# MyMiniHome — 기본 장면 v1 동작·입력·크기 운영 기준

작성: 2026-11-23 · 단일 템플릿: `scenes/forest-village-v1/index.html`

## A. 사용자 채택 방향과 실제 범위
- **유지할 확정 결정:** Q1~Q6(클릭 상호작용/아이소메트릭/기존 프로젝트·GPT 링크/동물 혼합/프로필 팝업/ChatGPT 내부 패널 목표).
- **이번 요청에서 채택한 운영 방향:** 기본 템플릿 **1종**에 집중; 장면 접지와 비율 개선을 먼저 하고, GitHub `main`은 최종본 중심으로 정리하되 **실사용 참조 경로와 자산 채택이 완료될 때까지 레거시 삭제를 실행하지 않음**; 조립 순서를 문서로 유지.
- **아직 확정하지 않은 것:** 개별 동물이 연결할 실제 프로젝트/GPT 및 URL, 최종 배경 시안의 사용자 승인, 안전 영역의 최종 좌표, 캐릭터 자유 이동/이동 경로 확장, 실제 ChatGPT 호스트의 사이드바 폭·모드, 텍스트 영구 저장/전송 여부.
- 현재 구현 파라미터(경로·속도·프레임 속도·최소 줌)는 **실험값**, 사용자 최종 미술·UX 승인값이 아님.

## B. 4개 질문별 현재 동작
### 1) 캐릭터 움직임
- 현재 장면의 **4종**(`squirrel/rabbit/fox/wolf`)이 지면 위치 기준의 서로 겹치지 않는 짧은 수평 동선에서 천천히 왕복함.
- 각 캐릭터의 6개 PNG를 움직이는 동안 **320ms 간격**으로 전환. 각 동물마다 이동 시간·잠시 멈춤 구간을 다르게 줌.
- 프레임 교체 시 상하·중심점 차이를 줄이기 위해 480×480 RGBA 프레임의 알파(128 이상) 바운딩박스 중심/하단을 기준으로 정렬 보정값 6개씩 추가. 로컬 ZIP 실측: squirrel 하단 편차 1px/중심 편차 8.5px; rabbit 10/21px; fox 16/27.5px; wolf 0/20.5px. 표시는 약 120px 크기로 축소되므로 보정은 최대 수 CSS px 범위.
- **다만 동물별 모션 시트는 특정 방향의 완전한 보행 애니메이션으로 제작·승인된 것이 아님**. 프레임이 실제 걷기 연출인지, 배경 가장자리의 잔상, 프레임 사이 움직임 자연스러움/발 지면 고정은 브라우저 시각 시험 후 판단.
- 캐릭터 클릭 시 이동을 중지하고 프로필을 표시. 모션 정지 버튼/시스템 `prefers-reduced-motion` 준수. 실제 길찾기·충돌 회피·방향별 걷기 그림은 미구현.

### 2) 오브젝트 반응
| 대상 | 현재 실제 동작 | 한계 |
|---|---|---|
| 오두막/독서 쉼터 | 해당 위치를 강조하고 개별 설명 패널 표시 | 실서비스 없음 |
| 빨간 우체통 | 80자 이내 한 줄 입력, 화면 내 메시지 미리보기 | 영구 저장·ChatGPT 전송 없음 |
| 나무다리 | 통행 구간 점선 강조 | 실제 경로 계획/충돌 처리 없음 |
| 연못 | 간단한 CSS 물결 표시 | 원본 물줄기·환경 프레임과 연결되지 않음 |
| 동물 4종 | 프로젝트/GPT 유형을 구별한 프로필 팝업 | 실제 URL은 `null`, 임의 링크 열기 없음 |

### 3) 화면/이미지 크기
- 마스터 장면 **1774×887px / 2:1**. 원본 배경은 화면 영역 너비에 맞춰 축소하되 **1배 초과 확대하지 않음**.
- 넓은 화면: **전체 장면 맞춤**. CSS 원본 폰트 크기가 아니라 장면 스프라이트 레이어만 `scale()` 대상으로 지정.
- 좁은 화면: 기본 줌 하한 **0.52배**를 유지하며 가로 스크롤로 탐색. 사용자가 '전체 보기/확대 보기' 토글 가능.
- 팝업과 텍스트 입력은 확대/축소되는 `stage` 밖에 배치: 데스크톱에서는 장면 가장자리 위의 별도 패널, 폭 740px 이하에서는 그림 아래 일반 흐름으로 배치해 글자/터치 영역 축소를 피함.
- 실제 ChatGPT 패널의 가용 너비/내부 안전 영역은 호스트 UI에서 검증 필요. 작은 창에서 사용자 선호도에 따라 0.52배를 조정 가능.

### 4) 대화·텍스트 입력
- **대화 본문과 AI 프롬프트:** ChatGPT 기본 composer 사용(Q6 요구사항), 동일한 챗봇 입력창을 미니홈피 HTML에 별도 구현하지 않음.
- **마을 내부 단기 안내:** 클릭한 캐릭터/오브젝트를 설명하는 `panel`만 사용. 대화 기록·채팅 상태와 혼동하지 않도록 기능을 구분.
- **우체통 한 줄 텍스트:** 화면 내 미리보기만 출력. 저장·외부 전송·AI 작업 지시 실행 없이 `textContent`로 안전 표시. 다른 오브젝트는 불필요한 입력란을 표시하지 않음.
- 실제 ChatGPT와 앱이 메시지를 주고받는 호스트 브리지 구현은 후속: 사용자 세션/권한/도구 호출 규격 확인 전까지 이번 HTML에서는 가짜 '전송 성공' 기능을 만들지 않음.

## C. 테스트 및 남은 검증
- GitHub에서 실제 HTML/JSON 재열람 후, **모의 DOM 실행 검증 통과:** 5개 핫스팟·4개 배우 생성, 프레임 자산 참조 25건 경로 존재, 캐릭터 좌표 갱신, 우체통 입력/미리보기/닫기, 다리 강조 해제, 연못 물결 표시, 캐릭터 프로필, 모션 일시정지, 420px '전체 보기' 전환.
- 기존 ZIP RGBA 알파 바운딩박스 **프레임별 24개 정적 측정** 및 보정값 생성.
- **실제 Chromium 시각·포인터·스크롤 렌더링 검증 미수행**: 위 모의 DOM은 브라우저 페인팅/사용감 확인을 대신하지 않음.
- **실제 ChatGPT Conversation Panel/MCP 호스트 연결 미수행**. 현재 HTML은 독립 웹 화면 시안.
- 사용자 승인 전: (1) 동물 4종 걷기 방향/표정/발지면 프레임 평가, (2) 배경의 물·지형 금지 영역 경로 검증, (3) 창 크기 360/420/740/1024/1440px 실제 브라우저 스크린샷 비교, (4) 클릭과 팝업 초점/스크롤 점검, (5) 캐릭터 8종 확대 배치 여부 결정.
- 레거시 자산 삭제·runtime 최종 승격·GitHub 히스토리 재작성은 이번 작업에 포함하지 않음.
